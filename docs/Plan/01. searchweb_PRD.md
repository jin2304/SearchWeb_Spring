> **문서 정보**

> - **작성일:** 2026-02-18
> - **문서 목적:** SearchWeb 프로젝트 전체에 대한 제품 요구사항(PRD) 기준 문서

<br>

## 1. Overview

SearchWeb은 사용자가 흩어진 웹 링크를 폴더/태그 기반으로 체계적으로 관리하고, AI를 통해 자동 분류하는 개인 링크 관리 서비스이다.

본 MVP는 **초기 사용자 50명 확보를 1차 목표로 설정하고, 이를 통해 실제 사용 데이터를 축적**하는 동시에 기존 단순 저장 구조를 고도화하여 링크가 **재탐색 및 재사용되는 구조를 구축·검증**하는 것을 목표로 한다.

### 🗺️ MVP 우선순위 및 핵심 가치 (Roadmap)
* **MVP1: 개인 북마크(링크) 관리**
    * **저장:** AI 자동분류/북마크/폴더/태그로 개인 지식 자산을 구조화한다.
    * **탐색:** 카테고리/검색 기반으로 사이트를 빠르게 찾는다.
* **MVP2: 팀 북마크(링크) 관리**
    * **공유:** 팀 폴더/게시판/댓글/좋아요를 통해 정보를 교환한다.
* **MVP3: 유용한 웹사이트 탐색**

## 2. Problem & Hypothesis

| 분류 | 📌 Problem (문제 상황) | 💡 Hypothesis (가설) |
| :--- | :--- | :--- |
| **문제 1. 재탐색** | - 브라우저 북마크는 폴더 기반 구조에 의존한다.<br>- 태그 기반 구조화 기능이 기본적으로 제공되지 않는다.<br>- 링크 수가 증가할수록 탐색 비용이 증가한다. | - 저장 대비 재열기 비율이 낮을 가능성이 높다.<br>- 저장 행위가 "보관"에 머물고 재사용으로 이어지지 않는다. |
| **문제 2. 관리 피로도** | - 폴더 선택 및 이동, 태그 입력 등은 사용자 수동 작업에 의존한다.<br>- 링크 누적 시 분류 부담이 증가한다. | - 일정 수 이상 링크가 쌓이면 정리가 중단된다.<br>- 태그 미입력 또는 무의미한 폴더 및 링크 누적 현상이 발생한다. |
| **문제 3. 구조화 부재** | - 기존 자료 관리 서비스는 문서·파일 중심 구조이다.<br>- 링크를 1차 객체로 구조화하는 서비스는 드물다. | - 링크가 개인 지식 자산으로 체계화되지 않는다.<br>- 누적될수록 서비스 가치가 비례 증가하지 않는다. |

## 3. Goal

### ① Product Level Goal
SearchWeb을 단순 저장 도구가 아닌 **재탐색과 재사용이 자연스럽게 발생하는 링크 관리 서비스로 구축한다.**

### ② MVP Level Goal (MVP1 기준)
* 폴더 + 태그 + AI 자동 분류 기반 구조를 구축한다.
* 링크 저장 시 정리 마찰을 최소화한다.
* 저장 이후 탐색 → 재사용 흐름이 발생하도록 UX를 설계한다.
* 사용자 행동 로그 체계를 구축하여 Baseline을 수립한다.

### ③ Goals (단계별 확장 목표)
* **G1 (MVP1):** 개인 북마크 관리 핵심 경험 제공
* **G2 (MVP2):** 팀 단위 북마크(링크) 공유/정리 경험 제공 (협업 기반 구조 확장)
* **G3 (MVP3):** 유용한 웹사이트 탐색/검색 경험 제공
* **G4 (공통):** 사용자 계정 기반 개인화 환경 제공 (로그인/프로필/마이페이지)
* **G5 (보조):** 커뮤니티 공유 기능 제공

### ④ Non-Goals (현 단계 제외 항목)
* AI 자동 분류/추천 품질 고도화(정확도 개선 및 고급 개인화 추천)
* 유용한 웹사이트 탐색/검색 경험 제공
* 모바일 네이티브 앱 동시 출시

## 📊 KPI (지속 추적 지표)

### ① 재사용 발생
* 저장 후 7일 내 재사용 경험 사용자 비율 **20% 이상**
* 탐색 기반 재사용 비율(검색/태그/폴더 → 재열기) **30% 이상**
* 사용자당 평균 주간 검색 사용 횟수 **1회 이상**

### ② 정리 효율
* 저장된 링크 중 AI 태그 포함 비율 **60% 이상**
* AI 추천 태그 채택률 **50% 이상**
* 수동 태그 수정 비율 **30% 이하**
* 링크 저장 완료 평균 소요 시간 **8초 이하**

### ③ 행동 루프 형성
* "저장 → 분류 → 탐색 → 재사용" 루프 경험 사용자 비율 **25% 이상**
* 링크 5개 이상 저장 사용자 중 검색 기능 1회 이상 사용 비율 **50% 이상**

### ④ 리텐션
* 7일 리텐션 **30% 이상**
* 링크 10개 이상 저장 사용자군의 30일 재방문율 **40% 이상**

### ⑤ 사용자 확보 (Growth Layer)
* MVP 출시 후 4주 내 가입 사용자 **50명 이상**
* 가입 사용자 중 **60% 이상** 첫 링크 저장 완료
* 가입 후 7일 내 1회 이상 링크 저장 사용자 비율 **50% 이상**

## 4. Target User

SearchWeb의 초기 타겟은 직업군이 아닌, **링크를 반복적으로 저장하고 재사용할 필요가 있는 사용자**이다.

### 🎯 Primary User – 링크를 축적하고 재사용하는 사용자
* **대표 유형:** 개발자, PM/기획자, 디자이너, 리서치·마케팅 직무 직장인, 대학생/취업 준비생
* **행동 특징:** 1개월 내 10개 이상 링크 저장 경험, 저장한 링크를 다시 찾는 데 어려움 경험, 정리 필요성을 인지하고 있음

### 🎯 Secondary User
* 링크 저장은 하지만 구조화 경험이 부족한 사용자
* 재사용 니즈가 아직 명확하지 않은 사용자

### 🎭 상황 기반 페르소나
1.  리서치 마감 직전 PM
2.  레퍼런스 수집형 디자이너
3.  과제 기반 대학생

<br>

## 5. User Flow

SearchWeb의 핵심 가치는 **저장 → 자동 구조화 → 탐색 → 재사용** 흐름에서 발생한다.



### ① 링크 저장 및 자동 구조화
1.  URL 입력
2.  AI가 제목·설명·태그 자동 생성 및 폴더 추천
3.  사용자 확인 (AI 생성 결과 그대로 사용 또는 수동 편집 후 저장)
4.  저장 완료

### ② 탐색 및 재사용
1.  홈 화면 진입
2.  검색 / 태그 클릭 / 폴더 선택
3.  필터링 결과 확인
4.  링크 재열기

### ③ 행동 루프
* **저장 → 자동 분류 → 탐색 → 재사용 → 반복**

<br>

## 7. Non-Functional Requirements (비기능적 요구사항)

### NFR-1. 성능 (Performance)
* **NFR-1.1:** 페이지 로드 시간 2초 이내 (초기 로드 기준)
* **NFR-1.2:** API 응답 시간 (일반 CRUD) 500ms 이내 (P95 기준)
* **NFR-1.3:** AI 자동 분류 응답 시간 5초 이내 (외부 API 호출 포함)
* **NFR-1.4:** 검색 결과 반환 시간 1초 이내

## 8. Scope

### ✅ In Scope
* **MVP 1: 개인 북마크(링크) 관리** (북마크/태그/폴더 CRUD, AI 자동 분석, 소셜 로그인, 행동 로그 수집 등)
* **MVP 2: 팀 북마크(링크) 관리** (팀 폴더/링크 관리, 공유 플로우, 어드민 페이지 등)
* **MVP 3: 유용한 웹사이트 탐색** (카테고리/검색 리스트, 저장 흐름 연결 등)
* **보조 기능:** 게시판 (게시글/댓글/좋아요)

### ❌ Out of Scope
* 링크 공유 기능
* 고급 AI 추천 시스템
* 외부 서비스 연동
* 통계 대시보드 고도화

## 🎯 최종 요약

SearchWeb MVP는 **초기 사용자 50명 확보를 1차 목표로 설정하고, 이를 통해 실제 사용 데이터를 축적**하는 동시에 **저장 이후 재사용이 발생하는 구조를 구축·검증하는 단계**이다.

핵심은 기능 확장이 아니라 **행동 루프(저장 → 자동 분류 → 탐색 → 재사용) 검증**과 **로그 기반 Baseline 수립을 통한 데이터 기반 제품 개선 체계 구축**이다.
